The Verilog module `avalon_memory_mapped_master` implements a simple Avalon Memory-Mapped master interface using a finite state machine (FSM) to manage read and write operations on a memory bus.

**Primary Function:**
The primary function of the module is to handle read and write transactions on an Avalon Memory-Mapped bus by generating appropriate control signals and transferring data based on input commands.

**Key Control Flow/Decision Points:**
1. **State Machine Initialization:**
   - The FSM starts in the `STATE_IDLE` state and transitions to other states based on the `start` signal, reset condition, and the memory operation's wait request status.

2. **Transaction Handling:**
   - In `STATE_IDLE`, if the `start` signal is asserted, the module sets up the address and byte enable signals. It then checks the `rnw` signal to decide between read (`READ`) and write (`WRITE`) operations, preparing necessary data for each operation.
   - The module then transitions to `STATE_WAIT` if `WAITREQUEST` is high, otherwise directly to `STATE_DONE`.

3. **Transaction Completion:**
   - In `STATE_WAIT`, the module remains until `WAITREQUEST` is low, after which it transitions to `STATE_DONE`.

4. **Done State:**
   - In `STATE_DONE`, if the operation was a read (`rnw` is high), the module captures the read data from the bus. The state then resets to `STATE_IDLE`, ready for the next operation.

**Important Data Processing or Signal Interactions:**
1. **Address and Control Signals:**
   - `ADDRESS_REG` holds the address for the memory access, which is output to the `ADDRESS` signal.
   - `BYTE_ENABLE_REG` sets the bytes affected in the transaction via the `BYTE_ENABLE` signal.
   - `READ_REG` and `WRITE_REG` signals indicate read or write operations.

2. **Data Handling:**
   - `WRITEDATA_REG` holds the data to be written when a write operation is performed.
   - `data_read_REG` captures data read from the bus when a read operation completes.

3. **Transfer Initiation and Completion Signaling:**
   - `BEGINTRANSFER_REG` and `BURSTCOUNT_REG` are prepared in the idle state for transfer initiation control.
   - The module signals the completion of a transaction by asserting the `done` output when in the `STATE_DONE` state.

Behavioral Clarifications:
- FSM has three states: STATE_IDLE=2'b00, STATE_WAIT=2'b01, STATE_DONE=2'b10. The state register uses a synchronous posedge CLK / posedge RESET always block; all other logic (next_state and datapath registers) is in a combinational always block sensitive to all signals. The done output is a combinational wire driven by (state == STATE_DONE).
