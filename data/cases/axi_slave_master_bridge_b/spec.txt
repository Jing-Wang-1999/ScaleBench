### Instruction for LLM to Generate Verilog Code

Create a Verilog module implementing an AXI protocol converter with the following functional description:

1. **Primary Function**: The module converts AXI slave interface signals to AXI master interface signals for read and write transactions. It manages AXI operations across five primary channels: write address, write data, write response, read address, and read data.

2. **Control Flow and Decision Points**:
    - Each channel (write address, write data, write response, read address, read data) has state management logic to handle different states: IDLE, BUSY, and default.
    - For the write address channel, when `s_axi_awvalid` is high, it transitions from IDLE to BUSY state, processes the address transfer, and waits for acknowledgment (`m_axi_awready`).
    - For the write data channel, when `s_axi_wvalid` is high, it transitions from IDLE to BUSY state, transfers write data, and waits for acknowledgment (`m_axi_wready`).
    - For the write response channel, it handles write responses from the master and updates the slave-side responses when `m_axi_bvalid` is asserted.
    - For the read address channel, it transitions from IDLE to BUSY if `s_axi_arvalid` is asserted and processes the address transfer until acknowledgment (`m_axi_arready`).
    - For the read data channel, it manages the read data responses from the master, transitioning from IDLE to BUSY when `m_axi_rvalid` is high and waiting for `s_axi_rready`.

3. **Data Processing and Signal Interactions**:
    - During write address and data transactions, the module copies relevant signals (`s_axi_awaddr`, `s_axi_awprot`, `s_axi_wdata`, `s_axi_wstrb`) from the AXI slave to the AXI master.
    - The write response management updates the AXI slave with the response received from the AXI master (`m_axi_bresp`).
    - During read transactions, the module transfers read addresses and processes the read data response, updating the slave interface signals (`s_axi_rdata`, `s_axi_rresp`).

4. **Implementation Details**:
    - The module includes state registers (`aw_state`, `w_state`, `b_state`, `ar_state`, `r_state`) to handle state transitions for each channel.
    - All channels have similar state transition logic encapsulated within always blocks sensitive to the rising edge of the clock (`aclk`) and active low reset (`aresetn`).
    - Dependencies and signal assignments are managed within the corresponding state logic, ensuring proper handshakes and data transfers between slave and master interfaces.

By incorporating the above details, you should be able to generate a Verilog module that accurately captures the primary function, key control flow, and data interactions for an AXI protocol converter.

Behavioral Clarifications:
- Each of the five channels uses a 4-bit state register initialized to IDLE (4'b0000) on reset (active-low aresetn). State encoding is IDLE=0, BUSY=1. Five separate clocked always blocks handle each channel independently.
- The read data channel sets s_axi_rlast to 1 unconditionally when transitioning to BUSY, and s_axi_rid and m_axi_bready are not driven by this module (s_axi_bid/s_axi_rid are not updated from master IDs in this implementation).
